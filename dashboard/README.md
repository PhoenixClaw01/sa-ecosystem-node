# Dashboard files

Static files for the public node. The Vercel project is `sa-ecosystem-node-dashboard`. It is separate from the DAO Council preview. The page reads the public Council sheet, public Solana RPC endpoints, public galaxy JSON, and a same-origin treasury cache. It does not sign, and it does not send form data.

`app.js` is the readable source of the preview that was already live. A minify of that source matched the previous bundle byte for byte, so the bundle copy was removed.

`dao.js` is generated from `src/dao` (`npm run build:dashboard-dao`). The monthly flows, payment ledger, balance chart, vote summary, revenue table, and PIP-23 limit use that file. Do not edit `dao.js` by hand.

`api/mcp.js` is the public MCP function, generated by `npm run build:dashboard-mcp`. Do not edit it by hand, and do not add TypeScript under `api/`.

`data/mcp-recorded.json` is generated by `npm run record-mcp` from the same tool code. Do not edit it by hand. The Ask the MCP tab on the dashboard page reads that file. `mcpEndpoint` stays empty there, so that tab does not call the live `/api/mcp` route. `/plain/` does call `/api/mcp`.

## Vercel

This directory is the Root Directory of the public node project `sa-ecosystem-node-dashboard`. The repository-root `vercel.json` is a different deploy: it rewrites `/mcp` to `api/mcp.ts` and is not the live site.

| Setting | Value |
|---|---|
| Root Directory | `dashboard` |
| Framework Preset | Other |
| Install Command | empty. The MCP function is a committed bundle and does not install this repo |
| Build Command | empty (`dashboard/vercel.json` sets `buildCommand` to `""`) |
| Output Directory | `.` (the dashboard directory) |
| Node.js | 22.x (`dashboard/package.json`) |

`api/mcp.js` is the public read-only Streamable HTTP function: `https://sa-ecosystem-node-dashboard.vercel.app/api/mcp`. No API key. See the root README for client setup, the timeout, the 512 KiB request and response caps, and the per-instance rate limit. `SOLANA_RPC_URL` and `SOLANA_RPC_FALLBACK_URLS` are optional overrides of the public defaults. `vercel.json` `includeFiles` lists `ata.js`, `squads.js`, `data/treasury-cache.json`, and `hub/signers.json`. `hub/signers.json` is a byte-for-byte copy of the repository `hub/signers.json`, written by `npm run build:dashboard-mcp`. Do not edit the copy. The same build embeds that file's sha256 in `api/mcp.js`. The function hashes the allowlist it loads and refuses the hub read when the bytes differ. The cache file is optional: the glob includes it only after the cache job commits it, and a missing match does not fail the build. The function also inlines `ata.js` and `squads.js`, so the static script tags stay unchanged. When `git` is absent, a pinned `github.com` hub is fetched over HTTPS.

`config.js` holds the public URLs for the static page. On the public project, `PUBLIC_HOME=plain` redirects a request for `/` or `/index.html` to `/plain/` with status 302 (`dashboard/middleware.js`). The hub pin and the approval threshold are the `HUB_*` variables in the root [docs/hosting.md](../docs/hosting.md). With `PUBLIC_HOME` unset, `/` serves the dashboard page in this directory. The public project does not leave it unset. The MCP server does not read `PUBLIC_HOME`.

## Jobs

- `.github/workflows/dashboard-snapshot.yml` runs `scripts/snapshot-balances.mjs` daily and commits only `dashboard/balances.json`.
- `.github/workflows/treasury-cache.yml` runs every 3 hours with `--incremental`. Each run fetches signatures newer than the cached cursor, then continues the older walk from the oldest parsed signature, inside the page cap. A concurrency group keeps runs from overlapping. It commits only `dashboard/data/treasury-cache.json`. Eight runs a day is about 240 runs in a 30-day month, about 240 Actions minutes if each run bills one minute, or about 480 if install pushes a run into a second minute.

Both jobs use the built-in `GITHUB_TOKEN` and the `github-actions[bot]` noreply identity. Until the treasury job has published a cache, the chain panels say the cache is missing. They do not fill in zeros.

## Plain page

`/plain/` shows listings, groups, hub updates, search results, and a player lookup as a card grid: one column on phones, two columns from 48rem, three from 68.75rem, and four on very wide screens from 93.75rem (`dashboard/plain/plain.css`). Cards in the grid start collapsed (`<details>` with no `open` attribute). Listings, groups, hub updates, and search each have Expand all, Collapse all, category filter chips, and a sort of A-Z, Newest, or Category (`dashboard/plain/plain.js`). The sort starts at A-Z. Groups are the guild rows from `hub_updates`. The page calls same-origin `/api/mcp` for `list_listings`, `hub_updates`, `search_hub`, `player_legacy`, and `player_story`. Under Listings there is one signed note, "What does signed mean?": "Signed means approved hub signers checked and published this record with their signing keys. It is not an endorsement, it is not proof of ownership, and it does not move money. The business is responsible for its own offer." The one payment line is: "This page does not take payment. Offers link to each business's own page." Each card can show the word Signed. `signedMeaning` is a field on `list_listings` results. The page does not print that field on each card.

On the public project, `PUBLIC_HOME=plain` redirects `/` to `/plain/`. The page is indexable: the HTML has no `noindex` tag, and `dashboard/vercel.json` sets no `X-Robots-Tag` on `/plain/`. It does send a Content-Security-Policy header. A Guides section near the top links the plain-language PDF, the tech spec, the public hub, and this source repository. There is no self-claim button on this page.

Logos are not proxied. Curators commit png, jpeg, or webp files into the hub repository. The page loads only that hub-relative path, resolved to `https://raw.githubusercontent.com/<owner>/<repo>/<40-character commit>/<path>`. `img-src` is `'self' https://raw.githubusercontent.com`. `'self'` covers the favicon. An external https logo stays in the signed listing and in MCP output, and this page does not request it. It shows a text initial instead. `http:`, `data:`, and `blob:` stay blocked. Each loaded logo is an `<img>` with `referrerpolicy="no-referrer"`, `loading="lazy"`, and a fixed 32×32 size. SVG is not used as an image source.
