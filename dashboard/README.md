# Dashboard files

Static files for the public node. The Vercel project is `sa-ecosystem-node-dashboard`.

`/` is `index.html`, the DAO dashboard front page: live DAO revenue by source and month (`dao_revenue`, from the public Galaxy treasury feed), a featured ecosystem tools section with each creator credited and linked out, live treasury and Ecosystem Fund figures (`treasury_balances`, `ecofund_limit`), and cards for the node's other tools. `home.js` makes those same-origin `/mcp` calls. A failed read shows "Data unavailable" and no figure. The featured section heading is the `FEATURED_HEADING` constant at the top of `home.js`. The one third-party view the page can frame loads only after a click, and `dashboard/vercel.json` allows only that origin in `frame-src`. Listing a tool there implies no affiliation or endorsement. `home.css` adds the layout on top of `styles.css`.

`.vercelignore` keeps the earlier dashboard page's scripts and data (`app.js`, `chain.js`, `config.js`, `dao.js`, `tracker.csv`, `balances.json`, `data/mcp-recorded.json`) and this README out of the deploy. They stay in the repository because tests and the CI checks still build and read them. `dao.js` is generated from `src/dao` (`npm run build:dashboard-dao`). Do not edit it by hand.

`api/mcp.js` is the public MCP function, generated by `npm run build:dashboard-mcp`. Do not edit it by hand, and do not add TypeScript under `api/`.

`data/mcp-recorded.json` is generated by `npm run record-mcp` from the same tool code for the CI check. Do not edit it by hand. It is not served.

## Vercel

This directory is the Root Directory of the public node project `sa-ecosystem-node-dashboard`. The repository-root `vercel.json` is a different deploy: it rewrites `/mcp` to `api/mcp.ts` and is not the live site.

| Setting | Value |
|---|---|
| Root Directory | `dashboard` |
| Framework Preset | Other |
| Install Command | empty. The MCP function is a committed bundle and does not install this repo |
| Build Command | empty (`dashboard/vercel.json` sets `buildCommand` to `""`) |
| Output Directory | `.` (the dashboard directory) |
| Node.js | 22.x (`dashboard/package.json`) |

`api/mcp.js` is the public read-only Streamable HTTP function: `https://sa-ecosystem-node-dashboard.vercel.app/api/mcp`. No API key. See the root README for client setup, the timeout, the 512 KiB request and response caps, and the per-instance rate limit. `SOLANA_RPC_URL` and `SOLANA_RPC_FALLBACK_URLS` are optional overrides of the public defaults. `vercel.json` `includeFiles` lists `ata.js`, `squads.js`, `data/treasury-cache.json`, and `hub/signers.json`. `hub/signers.json` is a byte-for-byte copy of the repository `hub/signers.json`, written by `npm run build:dashboard-mcp`. Do not edit the copy. The same build embeds that file's sha256 in `api/mcp.js`. The function hashes the allowlist it loads and refuses the hub read when the bytes differ. The cache file is optional: the glob includes it only after the cache job commits it, and a missing match does not fail the build. The function also inlines `ata.js` and `squads.js`, so the static script tags stay unchanged. When `git` is absent, a pinned `github.com` hub is fetched over HTTPS.

The hub pin and the approval threshold are the `HUB_*` variables in the root [docs/hosting.md](../docs/hosting.md). Nothing in this directory reads `PUBLIC_HOME` any more; `/` is never redirected. The MCP server does not read it either.

## Jobs

- `.github/workflows/dashboard-snapshot.yml` runs `scripts/snapshot-balances.mjs` daily and commits only `dashboard/balances.json`.
- `.github/workflows/treasury-cache.yml` runs every 3 hours with `--incremental`. Each run fetches signatures newer than the cached cursor, then continues the older walk from the oldest parsed signature, inside the page cap. A concurrency group keeps runs from overlapping. It commits only `dashboard/data/treasury-cache.json`. Eight runs a day is about 240 runs in a 30-day month, about 240 Actions minutes if each run bills one minute, or about 480 if install pushes a run into a second minute.

Both jobs use the built-in `GITHUB_TOKEN` and the `github-actions[bot]` noreply identity. Until the treasury job has published a cache, the chain panels say the cache is missing. They do not fill in zeros.

## Plain page

`/plain/` shows listings, groups, hub updates, search results, and a player lookup as a card grid: one column on phones, two columns from 48rem, three from 68.75rem, and four on very wide screens from 93.75rem (`dashboard/plain/plain.css`). Cards in the grid start collapsed (`<details>` with no `open` attribute). Listings, groups, hub updates, and search each have Expand all, Collapse all, category filter chips, and a sort of A-Z, Newest, or Category (`dashboard/plain/plain.js`). The sort starts at A-Z. Groups are the guild rows from `hub_updates`. The page calls same-origin `/api/mcp` for `list_listings`, `hub_updates`, `search_hub`, `player_legacy`, and `player_story`. Under Listings there is one signed note, "What does signed mean?": "Signed means approved hub signers checked and published this record with their agent record keys. Those are signing keys kept by each team's agent, separate from any wallet that holds funds. A player's own claim is still signed in that player's wallet. It is not an endorsement, it is not proof of ownership, and it does not move money. The business is responsible for its own offer." The one payment line is: "This page does not take payment. Offers link to each business's own page." Each card can show the word Signed. `signedMeaning` is a field on `list_listings` results. The page does not print that field on each card.

The home page links `/plain/`. The page is indexable: the HTML has no `noindex` tag, and `dashboard/vercel.json` sets no `X-Robots-Tag` on `/plain/`. It does send a Content-Security-Policy header. A Guides section near the top links the plain-language PDF, the tech spec, the public hub, and this source repository. There is no self-claim button on this page.

Logos are not proxied. Curators commit png, jpeg, or webp files into the hub repository. The page loads only that hub-relative path, resolved to `https://raw.githubusercontent.com/<owner>/<repo>/<40-character commit>/<path>`. `img-src` is `'self' https://raw.githubusercontent.com`. `'self'` covers the favicon. An external https logo stays in the signed listing and in MCP output, and this page does not request it. It shows a text initial instead. `http:`, `data:`, and `blob:` stay blocked. Each loaded logo is an `<img>` with `referrerpolicy="no-referrer"`, `loading="lazy"`, and a fixed 32×32 size. SVG is not used as an image source.

## MCP Playground

`/playground/` calls this site's own `/mcp` route from the browser. It lists every tool from `tools/list` and builds a form for each from its input schema. Run sends one `tools/call` and shows the raw JSON beside a short plain-English note that only restates the reply. Only tools the server marks `readOnlyHint: true` (and not `destructiveHint`) get a form. Nothing on the page signs, claims, or pays.

The Signed records panel loads `hub_updates`, rebuilds each record's canonical payload, checks it hashes to the record's `hash`, and verifies the author's ed25519 signature with WebCrypto. Small-order and non-canonical keys and R values, and an S at or above the group order, are refused first, the same rules as `src/hub/ed25519-verify.ts`. The tamper switch flips one byte of the signed bytes so the check fails. A kind the page cannot rebuild, a hash mismatch, or a browser without Ed25519 shows "Not checked", never a pass.

The Treasury panel reads `treasury_balances` and `ecofund_limit` live on each load. A failed call says "Live call failed" and shows no number for it. The Connect panel builds the MCP URL from the page origin, so it is right on any deployment. `dashboard/vercel.json` serves `/playground/` under a strict content policy (`script-src 'self'`, `connect-src 'self'`). Files: `playground/index.html`, `playground/playground.js`, `playground/verify.js`, `playground/boot.js`, `playground/playground.css`. Tests: `tests/playground.test.ts`.
